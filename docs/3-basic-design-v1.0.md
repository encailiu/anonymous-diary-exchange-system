# 匿名日記ランダム交換システム 基本設計書 v1.0

## 1. システム構成図

以下は写真・匿名コメントを含む目標構成である。現在の実装範囲は、Google Formsからの日記本文受付、Sheets上のマッチ・配信状態管理、Gmail配信、管理者通知までとする。写真、コメントWeb App、アーカイブは未実装である。

```text
                   ┌────────────────┐
                   │ Google Forms   │ (Googleログイン / 確認済みメールアドレス収集 / 日記投稿 / 任意写真)
                   └───────┬────────┘
                           ↓
                   ┌────────────────┐
                   │ Google Sheets  │ (データストア / 運用管理)
                   └───────┬────────┘
                           ↓
             [GAS / 時間指定トリガー 22:05]
            ┌──────────────┼──────────────┬──────────────┐
            ↓              ↓              ↓              ↓
       マッチング logic  履歴データ照合     Gmail配信処理   エラーハンドラ
            │              │              │              │
            ↓              ↓              ↓              ↓ (エラー時)
      Matches Sheet   History Update  参加者へメール送信   管理者(複数)へ通知
                                          │
                                          ↓ (コメントURL)
                                 Apps Script Web App
                                          │
                                          ↓
                                  Comments Sheet
                                          │
                                          ↓
                                 Gmail匿名コメント通知
```

## 2. 現行データモデル

| シート | 用途 |
| --- | --- |
| `Participants` | 参加者ID、内部メールアドレス、有効状態を管理する。 |
| `Diaries` | 日記日、投稿日時、本文、受付状態を管理する。無効・重複投稿のメールアドレスと本文は保存しない。 |
| `Matches` | 相互ペアまたはスキップと、配信の集約状態を管理する。 |
| `DeliveryLog` | 日記・受信者単位の `processing`、`delivered`、`error` を管理する配信状態の正本。 |
| `RunLog` | 日次処理と明示再送の結果を管理する。 |

`Comments` は匿名コメント実装時に追加する。

## 3. セキュリティと復旧設計

- Spreadsheet、Form ID、管理者アドレスは参加者へ公開しない。
- 参加者向けメールには日記本文以外の内部識別情報を含めない。
- 日次処理と再送はScript Lock内で行う。
- `error` は管理者の明示操作でのみ再送する。結果不明の `processing` は二重送信防止のため再送しない。
- 既存マッチに欠落・重複があれば配信を停止し、管理者へ通知する。
