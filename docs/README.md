# ドキュメント案内

このディレクトリには、匿名日記ランダム交換システムの仕様、設計、開発手順、進捗をまとめています。初めて読む場合は、下記の「推奨する読み順」に沿ってください。

## 推奨する読み順

1. [基本仕様書](1-basic-spec-v1.0.md)で、システムの目的と運営方針を把握する。
2. [要求仕様書](2-require-spec-v1.0.md)で、システムが満たすべき要件を確認する。
3. [基本設計書](3-basic-design-v1.0.md)で、全体構成とデータモデルを理解する。
4. [実装仕様書](4-impl-spec-v1.0.md)で、GASのモジュール境界と実装上の制約を確認する。
5. 実装・検証を行う場合は、[AIエージェント開発指示書](5-agent-dev-inst.md)と[実装チェックリスト](implementation-checklist.md)を参照する。
6. 2026年8月11日のレビューで検出した未対応事項は、[仕様・実装レビュー指摘事項](review-findings-2026-08-11.md)を参照する。

## 文書の地図

| 文書 | 役割 | 主な内容 | 参照する場面 |
| --- | --- | --- | --- |
| [基本仕様書](1-basic-spec-v1.0.md) | プロジェクトの出発点 | 目的、背景、対象ユーザー、利用シーン、サービスコンセプト、運営方針 | システムの狙いや対象範囲を確認するとき |
| [要求仕様書](2-require-spec-v1.0.md) | 機能・非機能要件の正本 | 投稿、JSTの締切、マッチング、匿名性、写真、コメント、メール、アーカイブ、障害対応 | 振る舞いや受け入れ条件を判断するとき |
| [基本設計書](3-basic-design-v1.0.md) | システム全体の設計 | Google標準機能による構成、コンポーネント、スプレッドシートのデータモデル、セキュリティ、復旧方針 | 機能間の関係や保存先を把握するとき |
| [実装仕様書](4-impl-spec-v1.0.md) | 実装詳細の正本 | GASのモジュール分割、配信状態、再送、匿名コメント、写真、アーカイブ、管理者通知、メール送信 | コードを追加・変更・レビューするとき |
| [AIエージェント開発指示書](5-agent-dev-inst.md) | 開発計画と検証要件 | 優先ルール、実装フェーズ、必須テスト | 次の実装作業や必要な検証を整理するとき |
| [実装チェックリスト](implementation-checklist.md) | 現在の進捗の正本 | 完了済み項目、Google実環境で未検証の項目、次回開始点 | 作業を開始・終了するとき、進捗を引き継ぐとき |
| [仕様・実装レビュー指摘事項](review-findings-2026-08-11.md) | 未対応問題のレビュー記録 | 検出した問題、影響、推奨解決策、完了条件、推奨対応順 | 改修計画を立てるとき、レビュー指摘を再確認するとき |

## 目的別の入口

- 要件を確認・変更する: [要求仕様書](2-require-spec-v1.0.md)
- データ構造やシステム構成を確認する: [基本設計書](3-basic-design-v1.0.md)
- GASの責務分担や安全な配信・再送方法を確認する: [実装仕様書](4-impl-spec-v1.0.md)
- 実装の優先順位と必須テストを確認する: [AIエージェント開発指示書](5-agent-dev-inst.md)
- 現在地と次に行う作業を確認する: [実装チェックリスト](implementation-checklist.md)
- 未対応のレビュー指摘と推奨解決策を確認する: [仕様・実装レビュー指摘事項](review-findings-2026-08-11.md)
- セットアップや実環境での確認を行う: [セットアップマニュアル](../SETUP.md) / [動作確認手順書](../VERIFICATION.md)

## 文書間の優先関係

内容が食い違う場合は、リポジトリ直下の [AGENTS.md](../AGENTS.md) にある不変条件を最優先とし、要求仕様、基本設計、実装仕様の順に意図を確認してください。匿名性、配信対象、データ削除の挙動に影響する曖昧さがある場合は、実装前に確認が必要です。

実装状況は仕様書から推測せず、[実装チェックリスト](implementation-checklist.md)を確認してください。チェック項目は、実装と対応する検証が完了した後に更新します。
